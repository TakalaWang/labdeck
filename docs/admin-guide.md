# 助教手冊

給負責實驗室主機帳號的助教（portal 的「管理員」）。部署與新增主機見 [deploy.md](deploy.md)，介面細節見 [api.md](api.md)。

原則：**學生不自己認領帳號**。任何人用 SSO 登入後只能「登記」需求，帳號與主機一律由助教在「待指派」建立或連結。
網頁左側「管理」選單：**待指派**、**人員與帳號**（人員／主機帳號）、**主機管理**（主機／健康）、**維運**（工作／公告管理／指南編輯／稽核紀錄）。
動到主機的操作都會變成「工作」（維運 → 工作，`/admin/ops?tab=jobs`），可以在工作頁看到輸出；指派主機的工作只動那一個帳號、自動執行，
其他會改變多個帳號或刪除帳號的工作都要先看預覽、按「確認執行」才會套用。

## 1. 開通新學生

1. 請學生用 SSO 登入 portal，到「登記」填寫姓名、希望的帳號名稱、用途、GPU 張數、每張最低顯存與預計使用期間。
   送出後網管頻道（Discord）會收到 `[帳號登記]` 通知。學生在指派前都可以修改登記。
2. 打開「待指派」（管理選單第一項；側欄會顯示待處理筆數，首頁也有「待指派 N 筆」卡片），找到這筆「新成員登記」，按「指派…」。
3. 帳號選「建立新帳號」：
   - 帳號名稱預設是學生希望的名稱，可以改。規則：小寫英文開頭，只含小寫英數字、`_`、`-`，最多 32 字；不能與任何人員或主機上看到的帳號同名
     （同名時會提示；若其實是同一個人，改用「連結既有帳號」，見第 2 節）。
   - 指派**不會設定帳號到期日**（新人員沒有到期日）。學生填的「預計使用到」只供參考；需要到期日時，指派後到人員頁設定並「同步」。
4. 挑主機。每張卡片顯示 GPU 型號與張數、每張顯存、**目前空閒卡數**與使用率、使用者人數（已認領、未停用的帳號；不含沒人認領的舊帳號）與主要使用者（★）、根目錄與資料碟剩餘空間；
   符合需求（空閒卡數與顯存都夠）的主機排在前面並標「符合需求」。監控資料取不到時數字顯示「—」，以主機頁或「使用量 → GPU 即時」為準。
   從未收集到資料（多半是還沒 bootstrap）或監控顯示離線的主機標「未 bootstrap／無法連線，指派會失敗」，排在最後且不能勾選（滑鼠移上去看原因）。
   多人共用同一台是正常的，挑負載較輕、主要使用者能接受的主機。
5. 按「建立帳號並指派」：系統分配全實驗室共用的 UID、建立人員，並對**每一台主機各排一個工作**，只建立這個帳號、不需預覽。
   幾分鐘內完成。**系統不會寄信通知學生**，請自行告訴他帳號已開通（不要傳密碼）；網頁上一律寫「助教指派後會通知你，也可以隨時回到我的帳號查看」。
6. 學生登入 portal 後首頁會出現「帳號已開通：請到我的帳號查看臨時密碼」。臨時密碼在**工作成功之後**才顯示（之前顯示「帳號建立中」，
   失敗則顯示「開通失敗，助教已收到通知」），重新整理也還在，直到學生按「我已記下」才刪除。「我的帳號」的「連線」欄有每台主機可複製的
   `ssh 帳號@位址` 與 `~/.ssh/config` 範例；第一次要用終端機 ssh 登入改密碼（新成員指南有寫）。
   若學生按了「我已記下」卻弄丟，請在主機上用 root 重設密碼並 `chage -d 0`。
7. 工作失敗時網管頻道會收到 `[失敗] 指派 xiaoming @gpu01（#12）：<原因>`。工作頁最上方有白話的失敗摘要（例如「主機尚未 bootstrap 或無法連線」、
   sudo 密碼不符），下方是完整輸出。常見原因：主機離線、還沒 bootstrap、已有同名帳號但 UID 不同。修正後在工作頁按「**重新執行**」
   （以目前的資料重新檢查後排入新的工作；人員已停用或已不再開通該主機時會拒絕）。

### 不指派時：退回或移除

每張待指派的卡片右上角有兩個按鈕，差別在**對方會不會知道**：

| | 退回 | 移除 |
|---|---|---|
| 對方看到 | 首頁與登記頁顯示「你的登記已被退回（日期）：<原因>。可修改後重新送出」，表單帶入上次內容 | 什麼都沒有，像沒送過一樣 |
| 通知 | 有設定 Email 時寄退回信（附原因） | 不寄信、不發 Discord |
| 紀錄 | 留在「已處理」 | 這筆直接刪除，只留稽核紀錄（`request_delete`） |
| 適用 | 認識的人但需求不合規定、要請他改（例如先和指導教授確認用途） | 重複送出、自己按錯、測試、不認識的人 |

兩者之後都可以重新登記或申請。拿不定主意就用「退回」並寫原因，對方才知道要怎麼改。

## 2. 連結已有帳號的舊成員

主機上早就有帳號的人（例如系統上線前就在用的學長姐）：

1. 先確定他的主機帳號已經「認領」成人員：「人員與帳號」→「主機帳號」→「建議認領」，勾選同名同 UID 的帳號批次認領；
   UID 不一致的到「UID 衝突」分頁逐台處理。認領後人員頁會有這個人，但還沒有 SSO ID。
2. 請他用 SSO 登入並填登記（用途裡寫上舊帳號名稱）。
3. 在待指派按「指派…」→「連結既有帳號」，搜尋他的帳號名稱或姓名並選取。這裡只列出還沒連結 SSO ID、未鎖定的人員。
4. 需要再加主機就一起勾選；不勾主機則只連結。按「連結帳號」（或「連結並指派」）。
   他的既有帳號與 UID 都不會改變；之後新開的主機會用一個新的全實驗室 UID（見 design.md 約定 F）。
5. 連結錯人時：到人員頁把 SSO ID 清空並儲存（有稽核紀錄），再重新處理登記。

## 3. 指派或移除主機

- **學生申請更多主機**：學生在「我的帳號」→「申請使用其他主機」填需求，會出現在待指派（「既有成員申請主機」）。
  按「指派…」挑主機即可，同樣每台一個自動工作。
- **快速指派**（不用等申請）：
  - 人員頁 →「指派主機…」→ 勾選主機 →「指派 N 台」。
  - 主機頁「使用者」分頁 →「新增使用者」→ 搜尋人員 →「指派」。
- **新增主機一律用「指派主機」**（人員頁、主機頁「新增使用者」或待指派）。
- **移除某台主機上的帳號**：主機頁「使用者」分頁（主要使用者卡片也有）或人員頁「主機帳號」每一列右邊的「移除」選單：
  - **鎖定…**：帳號不能再登入這台主機，家目錄與檔案都保留，其他主機不變。只有已認領的帳號可以鎖定（沒人認領的舊帳號只能刪除，或先認領）。
  - **刪除…**：`userdel`，可勾「同時刪除家目錄」（要輸入帳號名稱確認），細節見第 5 節。
  - 兩者都會**先產生預覽工作**，按「查看」到工作頁確認預覽後才執行。`root`、bot 帳號與 `RESERVED_USERS` 沒有這個選單。
- **一次停用或恢復多台**：人員頁「停用／恢復主機帳號」取消勾選 →「更新」→「同步」→ 到工作頁看預覽並確認。帳號會被鎖定（不刪除、資料保留），
  之後在同一處重新勾選並同步就能恢復（單台「鎖定」的帳號也從這裡恢復）。這裡只列出已開通過的主機，不能新增主機。
- **預檢失敗**：需要預覽的工作（同步、刪除帳號）如果連預覽都跑不起來（例如主機無法連線），工作狀態是「預檢失敗」、不能確認執行，
  網管頻道收到 `[預檢失敗] …`。修正主機後按「重新執行」重新預覽。
- **主要使用者**：主機頁「使用者」分頁的帳號列表按星號；會顯示在主機列表與指派時的主機卡片上，方便學生知道該找誰協調。

## 4. 公告與維護

- 「維運」→「公告管理」新增公告。只是通知就填標題、內容與顯示期間；有維護窗口就勾選受影響的主機（會出現在「公告與維護 → 維護日曆」與 iCal）。
  也可以在維護日曆點某一天的「新增維護公告」，預填當天 09:00–18:00。
- 公告不會對主機做任何事：**系統已不提供排程關機與遠端電源控制（IPMI）**。需要關機或重開時請到現場或用主機自己的管理介面處理，
  並在公告寫清楚時間。以前排的關機工作仍留在工作紀錄裡（標「已停用」），不會再執行。
- 有帳號在受影響主機、並訂閱了維護通知的成員，會在公告發布時與開始前 24 小時收到通知。

## 5. 畢業生與不再使用的帳號

**畢業或離開實驗室的成員用「移除成員」**（人員頁右上角，或人員列表每一列右邊的「移除」）：

1. 對話框列出這個人在每台主機的帳號，每台選一種處理方式：
   - **鎖定**（預設）：不能登入，家目錄與檔案保留，之後可以恢復。不確定學生資料是否已備份時一律先選這個。
   - **刪除**：從主機刪除帳號；需要時勾「同時刪除家目錄」並輸入帳號名稱確認（見下方刪除的注意事項）。主機上還沒看到的帳號只能鎖定。
2. 按「移除成員」後：
   - 每台主機各排一個**預覽工作**，到「維運 → 工作」看預覽、按「確認執行」才會真的鎖定或刪除（不會自動執行）。
   - 人員狀態變成「**已移除**」：清除 SSO 身分、Discord 與 Email 通知連結，對方無法再以成員登入（已登入的也會立刻失效）；
     他等待中的登記或主機申請一併關閉（不寄信）。網管頻道會收到 `[移除成員] …`。
   - 人員紀錄**不會刪除**：人員列表切到「已移除」可以查到，帳號、金鑰與稽核紀錄都還在。
3. 之後確定不再需要時，再到主機頁「使用者」或人員頁「主機帳號」對鎖定的帳號選「移除 → 刪除…」。
4. 不能移除自己，也不能移除最後一位啟用中的管理員。移除其他管理員不會改角色（網頁上沒有降級，見第 7 節），但他已無法登入。
5. 移除錯人：取消還沒確認的預覽工作，在人員頁把狀態改回「啟用」、重新填入他的 SSO ID 並儲存，再用「停用／恢復主機帳號」或「指派主機」恢復主機帳號
   （已刪除的帳號要重新指派，檔案無法復原）。

只想停用、還沒要離開的人（例如休學）：人員頁把狀態改成「鎖定」並儲存，所有主機的帳號都會變成停用，按「同步」並確認預覽後套用；
鎖定可以隨時解除，資料都在。到期日到了的人員也會自動不能登入（帳號到期日由 shadow 控制）。

**刪除帳號的注意事項**（「移除 → 刪除…」與「移除成員」選刪除時都一樣）：
- 刪除是**一台一台**做的，而且一定先產生預覽工作，要到工作頁確認才會執行（`userdel`）。帳號還有程序在跑時會失敗。
- 勾「同時刪除家目錄」時必須輸入帳號名稱確認；檔案無法復原，刪之前先確認學生已備份、指導教授同意。
  家目錄必須是 `…/<帳號名稱>` 且屬於該帳號，否則整個工作失敗、什麼都不刪（避免誤刪共用目錄）。資料碟（`/data*`）上的檔案不會被刪。
- 沒人認領的舊帳號也可以直接刪除，不需要先認領。
- 預覽後不想刪了：取消工作，再到人員頁用「指派主機」把該主機加回來（或重新認領）。
- `root`、bot 帳號與 `RESERVED_USERS` 列出的帳號永遠不能鎖定、刪除或修改（主機帳號列表標「保留帳號」，沒有認領或移除按鈕）；學生登記也不能用這些名稱。

## 6. 日常檢查

- 「主機管理」→「健康」：無法連線、磁碟快滿、apt 更新失敗、GPU 掉卡等（主機列表的「健康」欄與各主機頁「概況」也看得到）。
- 「人員與帳號」→「主機帳號」→「漂移」：應開通卻不存在、應停用卻沒鎖、待刪除等，按人員頁「同步」修正。
- 「維運」→「工作」：失敗（含預檢失敗）的工作與等待確認的預覽。每筆工作以白話描述（例如「指派 xiaoming @gpu01」「刪除 oldgrad @gpu01」）。
- 「維運」→「稽核紀錄」：誰在什麼時候指派、連結、刪除、升級了什麼（動作欄是中文，滑鼠移上去看原始代碼）。

## 7. 管理員

- **設為管理員**：人員頁右上角「設為管理員」→ 確認對話框會寫出這個人的姓名與帳號 →「設為管理員」。只能升級帳號啟用中、未到期的成員；
  已是管理員時沒有這個按鈕。會寫稽核紀錄（`person_promote`）並在網管頻道（Discord）發 `[管理員] … 將 … 設為管理員`。
- **網頁上沒有降級**：人員頁不能改角色，API 也一律拒絕（`403`）。這是刻意的：被盜用的管理員帳號無法用網頁把其他管理員降級。

### 緊急程序：移除管理員權限

只有能登入監控主機、操作 docker compose 的伺服器管理者能做。例如管理員帳號被盜用、助教離職：

```sh
docker compose exec web labdeck demote-admin <帳號名稱>      # runner 容器內也有同一個指令
```

- 成功時印出 `<帳號> is no longer an admin`，寫稽核紀錄（`admin_demote`，actor 為 `cli`），並在網管頻道發通知。對方下一個請求起就沒有管理權限。
- 為避免沒有任何管理員，**最後一位啟用中的管理員不能降級**；先用 `labdeck add-admin <sso_id> <帳號名稱>` 加另一位再降級。
- 若帳號被盜用，另外在人員頁把該人員「鎖定」（或清空 SSO ID）並請對方更換身分提供者的密碼。助教離職則可直接「移除成員」（第 5 節），
  但要移除的是最後一位啟用中的管理員時，請先加另一位管理員。
