# 歡迎使用 {{site_name}}

這份指南帶你從登記帳號到開始跑實驗。有問題先看最後的「求助」一節。

## 1. 登記

1. 以 **{{oauth_name}}** 登入 {{site_name}}。
2. 到「[登記](/request)」填寫：
   - **姓名**、**希望的帳號名稱**：小寫英文開頭，可含數字、`_`、`-`。所有主機使用同一個名稱與 UID，助教可能依實際情況調整。
   - **用途**、**GPU 張數**、**每張最低顯存**（選填）與**預計使用到**的日期。不用選主機，助教會依需求與各主機的負載指派。
3. 送出後同一頁會顯示登記內容；指派前都可以修改。

如果你以前就在實驗室主機上有帳號，一樣填寫登記，並在用途註明舊帳號名稱，助教會把它連結給你。

## 2. 等待指派

首頁會顯示「已收到你的登記，等待助教指派」。助教指派後會通知你，也可以隨時回到「我的帳號」查看（開通的主機、建立進度都在那裡）。等待期間你仍可以看這份指南與公告，但主機、GPU 看板等頁面要等帳號開通後才能使用。

如果登記被退回，首頁與「[登記](/request)」頁會寫出原因，修改後可以重新送出（表單會帶入上次的內容）。

> 若等了很久沒有消息，請聯絡助教，並附上你的 {{oauth_name}} 帳號與登記時間。

## 3. 第一次登入（改密碼）

1. 帳號建立完成後，首頁會提示「帳號已開通」，「[我的帳號](/me)」最上方會顯示**臨時密碼**（建立中時會寫「帳號建立中」）。記下後按「**我已記下**」，系統就會刪除它，之後無法再查看。
   這個臨時密碼適用於所有新建的主機帳號；改密碼後各主機各自獨立。
2. 用**終端機**登入任一台主機（Windows 可用 PowerShell 內建的 `ssh`）。登入指令在「[我的帳號](/me) → 主機帳號」表格的「**連線**」欄，可直接複製，格式是：

   ```bash
   ssh <帳號>@<位址>
   ```

3. 系統會要求先輸入臨時密碼（Current password），再輸入兩次新密碼，然後自動斷線。重新登入即可。

**注意**：第一次一定要用終端機互動登入。VS Code Remote-SSH、`scp`、`sftp`、`rsync` 等工具無法完成「強制改密碼」這一步，會一直登入失敗，直到你用終端機改好密碼為止。

## 4. 上傳 SSH 金鑰

用金鑰登入比密碼安全，也是 VS Code Remote-SSH 最順的用法。

1. 在自己的電腦產生金鑰（已經有就跳過）：

   ```bash
   ssh-keygen -t ed25519 -C "you@laptop"
   ```

2. 把**公鑰** `~/.ssh/id_ed25519.pub` 的內容貼到「[我的帳號](/me) → SSH 金鑰」。系統會自動部署到你所有的主機帳號，通常一兩分鐘內生效。
3. 建議在 `~/.ssh/config` 加上主機設定，之後 `ssh gpu01` 就能登入。「[我的帳號](/me) → 主機帳號」下方有已填好你所有主機的設定可以直接複製，格式是：

   ```
   Host gpu01
       HostName <位址（見「連線」欄）>
       User <帳號>
       IdentityFile ~/.ssh/id_ed25519
   ```

**私鑰**（沒有 `.pub` 的那個檔案）絕對不要貼給任何人或上傳到任何地方。換電腦或私鑰外洩時，請在「我的帳號」撤銷舊的金鑰。

## 5. 找空卡

1. 打開「[使用量 → GPU 即時](/usage?tab=gpu)」：每張卡的使用率、記憶體與正在使用的人一目了然；「閒置」代表使用率低於 5% 且記憶體用量低於 1 GiB。
2. 登入主機後用 `nvidia-smi` 再確認一次，然後用 `CUDA_VISIBLE_DEVICES` 指定要用的卡（編號同 `nvidia-smi`）：

   ```bash
   CUDA_VISIBLE_DEVICES=2 python train.py
   CUDA_VISIBLE_DEVICES=2,3 torchrun --nproc_per_node=2 train.py
   ```

3. 不指定的話，多數框架會佔用**所有**看得到的卡，影響其他人。
4. 長時間的工作請在 `tmux` 或 `screen` 裡執行，斷線也不會中止。
5. 用完請結束程式，不要讓 process 佔著顯示卡記憶體卻沒有在算。

## 6. 磁碟與資料存放規範

- **家目錄**（`/home/<帳號>`）空間有限，放程式碼、設定檔與小檔案。
- **資料集、checkpoint、實驗輸出**請放在主機的資料碟（實際路徑依各主機掛載點與實驗室規定），不要塞滿家目錄或 `/tmp`。
- 定期清掉不需要的 checkpoint 與暫存檔。各人用量可在「[使用量 → 磁碟](/usage?tab=disk)」查看（每晚或每週掃描一次）。
- 主機**不保證備份**。論文、程式碼等重要資料請自行備份到其他地方（例如 git 遠端、雲端硬碟）。
- 磁碟寫滿時，同一台主機上所有人的工作都可能失敗。

## 7. 帳號到期

- 帳號到期日顯示在「[我的帳號](/me)」，到期日當天結束前都能使用。
- 到期後主機上的帳號會被鎖定，無法登入；檔案不會立即刪除，但請在到期前搬走需要的資料。
- 需要延長請在到期前聯絡網管。

## 8. 求助

1. 先看「[公告與維護](/announcements)」與其中的「[維護日曆](/announcements?tab=calendar)」，確認不是維護時段。
2. 聯絡網管時請附上：
   - 你的帳號與主機名稱
   - 發生時間
   - **完整的錯誤訊息文字**（複製貼上，不要只給截圖）
   - 你執行了什麼指令、做了什麼操作
